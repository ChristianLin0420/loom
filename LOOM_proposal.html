LOOM v0.4 · implementation proposal

Operator-native control

The action is the operator. Two losses carry the representation: Ldyn for what a transformation does, Lact for how this body produces it. Goal of this document: build it and read the success rate.

Build order

fork lerobot v3.0 as the single spine
  1. data loader — LeRobot v3.0 multi-stream reader. Variable camera count per embodiment, tactile treated as an ordinary RGB view. Frozen-encoder features cached to disk once; never re-encoded.
  2. estimator E — Perceiver cross-attention block, K=128 learned queries over (all modality tokens ⊕ z_{t−1}). Verify a single forward runs at ≥ 30 Hz on one A100 with 7 streams.
  3. operator bank — M=128 × 384 real 2×2 rotation-decay blocks. Radius r = ρ·sigmoid(θ), angle ω free. Assert ‖A(c)‖₂ ≤ ρ numerically on random simplex draws.
  4. q_Δ + top-k — straight-through top-4 with renormalisation so c stays on the simplex. This is what makes the contractivity bound hold; do not substitute a plain softmax.
  5. imaginer — batched composition A(c_H)⋯A(c_1)z. Must be a single fused elementwise kernel over the block-diagonal, not a matmul loop. Target: 1000 candidates × depth 4 under 5 ms.
  6. L_dyn — InfoNCE with in-batch negatives drawn from other transitions. Uncurated negatives; do not group by task or embodiment.
  7. q_a + D_e — q_a regresses sg(q_Δ), so both write into one coefficient space by construction. D_e is flow matching on (z, c).
  8. Φ + π_c + MCTS — 128-arm MCTS, depth 4, PUCT with π_c as prior. Only built for Run 3.
Single build assert. During training, log d(A(c_true)z, z⁺) − d(A(c_random)z, z⁺). If this gap sits near zero, c is being ignored, A(c) ≈ I, and the model has silently degenerated into a plain latent policy. Not a research metric — a unit test that the architecture is wired.
